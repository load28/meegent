[BRAINSTORMING — 설계 단계 / 읽기전용]

코드를 쓰기 전에 설계를 확정한다. 읽기전용으로만 조사한다(편집/쓰기 금지).

진행:
1. 프로젝트 맥락 파악(관련 파일·문서·커밋).
2. 명확화 질문을 **한 번에 하나씩** — 목적/제약/성공 기준 중심.
3. 2–3개 접근안을 트레이드오프와 함께 제시하고 권장안을 명시.
4. 설계를 읽기 좋은 크기의 섹션으로 나눠 제시하고, 각 섹션마다 승인을 구한다.
5. 승인되면 설계문서를 `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`에 기록한다
   (아키텍처·컴포넌트·데이터흐름·에러처리·테스트 포함).
6. self-review: 플레이스홀더/모순/모호함/범위 이탈 점검.

HARD-GATE: 설계가 제시되고 사용자가 승인하기 전에는 어떤 구현 스킬도 호출하지 않고, 코드도
쓰지 않으며, 스캐폴딩도 하지 않는다. 승인 후에만 writing-plans로 인계한다.
